# Stop the registration from telling who has a User

Status: needs-triage
Type: feature

> *This was generated by AI during triage.*

## Problem

`POST /api/v1/auth/register` answers `409 auth.email_in_use` for an address that has a User. Anyone can therefore learn who has a User with one request and no time measurement, and the same response of the password reset request route (`.scratch/password-reset/spec.md`) does not close this path.

## Solution

The route answers the same way for both kinds of address, and an email tells the owner of the address what happened. This changes the registration flow, because a client no longer learns from the response that the address is in use.
